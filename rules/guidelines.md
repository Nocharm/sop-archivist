# Working Style

Claude Code 기본 지침(단순하게, 고칠 곳만, 실행해서 검증)에 더해 이 저장소에서만 정한 것. 아래 도메인 규칙과 부딪히면 이 문서가 먼저다.

## 물을 때 · 진행할 때

- 결과가 갈리는 모호함(API 모양 · 자료 구조 · 사용자가 보는 동작) → 먼저 묻는다.
- 겉모양이거나 되돌릴 수 있는 것(이름 · 파일 자리 · 순서) → 가정을 적고 진행한다.
- 사용자가 정한 것(명세의 결정 항목, 장부의 "사용자 답")은 다시 묻지 않고 빼지 않는다.

## 검증과 멈춤

- "통과"는 명령을 돌려 초록을 본 것만. 돌릴 수 없으면 무엇을 못 봤는지 그대로 말한다.
- 같은 고침을 두 번 했는데 나아지지 않으면 멈추고 막힌 곳을 말한다.
- 경고 · 타입 오류가 남은 채 끝났다고 하지 않는다. 오류를 `|| true` · `2>/dev/null` · 삼키는 try로 가리지 않는다.
- 범위 밖에서 찾은 것은 고치지 않고 끝에 한 줄로 알린다(따로 브랜치 — 루트 CLAUDE.md "일 크기에 맞는 절차").

## 말하기

- 설명은 한국어, 코드 · 식별자 · 오류 메시지 · 커밋/PR 글은 영어(커밋 제목은 영/한 병기, `git.md`). 기술 문자열은 글자 그대로.
- 결론 먼저, 군말 없이. 여러 파일을 고쳤으면 경로부터.
- 보고는 "무엇을 바꿨고 어떻게 확인했는지"를 다섯 줄 안에. 가정했으면 "X로 가정 — 맞나요?"
