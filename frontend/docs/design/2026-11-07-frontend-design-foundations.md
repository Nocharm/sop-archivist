# SOP Archivist 프런트 디자인 기초

컨셉 세션에서 사용자와 정한 프런트 디자인 결정이다. 화면 코드 주석이 `디자인 문서 N절`로 이 문서의 절 번호를 참조하니 번호를 바꾸지 않는다(구현 세션 인계용 0·1절은 v0.4.0 머지 뒤 지웠다).

- 작성일: 2026-11-07
- 상태: 디자인 컨셉과 16절의 동작 결정 3개 확정, 1차 화면은 v0.4.0으로 구현됐고 v0.5.0에서 검토 수정을 반영했다.
- 토큰: `frontend/src/styles/tokens.css`가 값의 단일 소스다(시안과 49개 색 값이 라이트·다크 모두 일치함을 확인했다). 시안 페이지는 비공개 디자인 세션 산출물이라 저장소에 두지 않는다.

## 2. 의도

SOP Archivist는 품질 조직의 SOP Restructuring T/F가 옛 GMP SOP를 새 SOP와 WI로 재구성하는 사내 도구다. 사용자는 수백 문장을 읽고 보낼 곳을 고르고 확정한다. 코드는 세고 AI는 제안만 하며 사람이 확정한다. 원문은 바뀌지 않는다.

그래서 디자인의 일은 세 가지다.

- 글이 많은 화면을 오래 봐도 편해야 한다.
- 다음에 할 일이 먼저 보여야 한다.
- 렌더 중 튀지 않고 손이 덜 움직여야 한다.

컨셉은 **제안은 연필로, 확정은 잉크로**다.

| 표시 | 뜻 |
|---|---|
| 점선 | 사람이 아직 보지 않은 제안. 코드가 낸 한/영 짝 제안도 포함한다 |
| 잉크색 실선과 채움 | 사람이 확정한 것. 주 버튼과 같은 색이다 |
| 한 줄 취소선 | 삭제. 원문은 읽혀야 한다 |
| 보라색 | AI가 낸 것에만 쓴다 |

## 3. 목표와 범위

**목표**

- 묶음 목록, 개요, 문서, 쪼개기, To-Be, 입구 2 수동 짝 맞추기, 분류, 결과물, 검토를 이 토큰과 규칙으로 만든다.
- 분류와 짝 맞추기는 사람 경로로 먼저 끝까지 동작하게 하고 AI 제안 자리만 잡는다.
- 토큰은 처음부터 라이트·다크 두 벌로 넣는다. 다크는 v0.4.0에서 실제 글자 대비 감사를 통과한 뒤 공개했다.

**1차 범위 밖**

- 문서 번호나 Note 같은 일부 표현의 이탤릭. 실제 문서를 보며 나중에 맞춘다.
- 원본 문서의 글꼴과 서식 재현. 추출기가 저장하지 않는다(14절).
- (v0.4.0에서 붙임) AI 제안 표시와 "AI에 묻기". 작업 상태는 v0.5.0부터 폴링한다.
- 관리 탭(지침·프롬프트 버전, 묶음 메타 목록). 명세 §12에는 있지만 1차 프롬프트의 순서에 없어 뒤로 미룬다.

**하면 안 되는 것**

- 도장, 서명, 승인처럼 보이는 표현. 확정은 일반 버튼이고 전자서명이 아니다. `done`은 "Review complete"이고 "approved"가 아니다(명세 §6.8, §10). 정식 승인은 Veeva에서 한다.
- 유사도 점수나 퍼센트 표시(명세 §12).
- AI 제안 일괄 확정. 일괄은 삭제, 이동, 코드가 확인한 입구 2 짝에만 허용한다(명세 §7.7).
- 용지 안에 앱 글자 넣기. 용지에는 추출한 글자만 둔다. 머리말과 꼬리말도 원문 단위다(명세 §6.3).
- 형광 배경 강조와 문장 전체 이탤릭. 사용자가 뺀 것이다.
- bpm의 시각 스타일(바이올렛, 유리 효과). bpm은 동작 규칙만 참고한다.

## 5. 토큰 적용

- `frontend/src/styles/tokens.css`가 값의 기준이다. 색을 바꾸면 이 파일만 고친다.
- 기존 로그인과 관리자 화면이 깨지지 않아야 한다. `frontend/scripts/pw-smoke-baseline.mjs`가 쓰는 `top-bar-*` 식별자는 그대로 둔다.
- raw hex는 토큰 파일 밖에서 쓰지 않는다. 틴트는 흰색이 아니라 표면색과 섞는다. 글자색(`-ink`)과 채움색(`-fill`)을 나눠 쓴다.
- 다크는 토큰만 바꾼다. 화면 코드가 테마를 분기하지 않는다.

## 6. 글꼴

| 역할 | 글꼴 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| 강조 | Gmarket Sans | 브랜드, 화면 제목, 단계 번호, 고정된 큰 숫자 | 표 안, 버튼, 원문, 바뀌는 숫자 |
| 본문 | Pretendard | 버튼, 표, 안내, 설명 전부 | |
| 식별자 | JetBrains Mono | 단위 ID, 문서 번호, 규칙 코드, 단축키 | 문장 |
| 원문 | 사용자 설정 | 용지 위 원문, 새 문장 | 앱 글자 |

**글꼴 파일.** 사내망이라 빌드 때 외부 다운로드를 할 수 없다. 파일을 저장소에 넣고 `next/font/local`로 읽는다. 라이선스 파일을 같이 넣는다.

| 글꼴 | 파일 | 처리 |
|---|---|---|
| Pretendard | `frontend/src/app/fonts/PretendardVariable.woff2` | 원본 그대로 |
| Gmarket Sans | `frontend/src/app/fonts/ArchivistAccent-{Medium,Bold}.woff2` | 아래 라이선스 처리대로 이름을 바꿨다 |
| JetBrains Mono | `frontend/src/app/fonts/JetBrainsMono-{Regular,SemiBold}.woff2` | 정식 배포본 그대로(Nerd Font 패치본은 쓰지 않는다) |

라이선스는 `frontend/src/app/fonts/licenses/`에 함께 둔다.

**Gmarket Sans 라이선스.** 파일 안 표기는 SIL OFL 1.1이고 예약 글꼴 이름 `Gmarket Sans Font`가 있다. 글자를 줄이거나 형식을 바꾼 사본은 수정본이라 그 이름을 쓸 수 없다. 권장안은 글자를 줄이지 않고 이름을 `Archivist Accent`로 바꾼 woff2다(Medium 약 500KB, Bold 약 577KB). 묶음 제목에 어떤 한글이 올지 모르므로 글자는 11,172자 그대로 둔다. 원본 TTF를 그대로 넣어도 되지만 굵기당 2.4MB다.

**강조 글꼴 제약.** 시안에서 재서 확인한 값이다.

| 항목 | 잰 값 | 처리 |
|---|---|---|
| 숫자 폭 | 0.45em에서 0.69em까지 제각각이고 `tnum`이 없다 | 확정하면 바뀌는 숫자는 본문 글꼴 `tabular-nums`로 둔다 |
| 세로 위치 | 세로 값이 800/200, 800/350 두 벌이라 OS마다 달라질 수 있다 | `ascent-override: 82%`, `descent-override: 18%`, `line-gap-override: 0%`. `next/font/local`의 `declarations`로 준다 |
| 기준선 | 글자가 기준선 아래로 약 0.08em 내려가 있다 | 본문 글꼴과 한 줄에 섞지 않고 칸을 나눈다 |
| 라틴 크기 | 대문자 높이가 Pretendard의 1.13배다 | 기본 언어가 영어라 제목 크기는 영어 기준으로 맞춘다 |

위 보정 값이면 글자 중심이 줄 중심에서 100px당 0.3px 안에 든다(Chrome 측정).

## 7. 사용자 설정

네 가지를 사람마다 브라우저에 저장한다. 서버에 저장하지 않는다.

| 설정 | 저장 키 | 값 | 기본 | 놓는 곳 |
|---|---|---|---|---|
| 전체 틀 | `sopa.shell` | `rail`, `bar` | `rail` | 상단 막대 배치 버튼 |
| 분류 배치 | `sopa.classifyLayout` | `paper`, `list` | `paper` | 상단 막대 배치 버튼 |
| 원문 한글 | `sopa.sourceFontKo` | `pretendard`, `malgun`, `batang` | `pretendard` | 용지 위 Aa 버튼 |
| 원문 영어 | `sopa.sourceFontEn` | `arial`, `pretendard`, `times`, `calibri` | `arial` | 용지 위 Aa 버튼 |

- 값은 `<html>`의 data 속성으로 내리고 CSS가 받는다. 시안은 `data-shell`, `data-layout`, `data-src-ko`, `data-src-en`을 쓴다.
- **첫 화면이 튀면 안 된다.** 저장된 값이 기본값과 다른 사람에게 기본 배치가 먼저 보이면 안 된다. 첫 페인트 전에 속성을 정한다. 지금 `sopa.lang`은 마운트 뒤 복원이라 이 방식을 그대로 쓰면 튄다.
- 맑은 고딕, 바탕, Arial, Times New Roman, Calibri는 PC 글꼴 이름만 쓰므로 저장소에 파일을 넣지 않는다. 없는 PC에서는 대체 글꼴로 보인다.

```css
[data-src-ko="pretendard"] { --font-source: var(--font-ui) }
[data-src-ko="malgun"]     { --font-source: "Malgun Gothic", "Apple SD Gothic Neo", sans-serif }
[data-src-ko="batang"]     { --font-source: Batang, AppleMyungjo, serif }
[data-src-en="arial"]      { --font-source-en: Arial, Helvetica, sans-serif }
[data-src-en="pretendard"] { --font-source-en: var(--font-ui) }
[data-src-en="times"]      { --font-source-en: "Times New Roman", Times, serif }
[data-src-en="calibri"]    { --font-source-en: Calibri, Carlito, Arial, sans-serif }
```

영어 원문은 `:lang(en)`으로 잡는다. 단위마다 `lang`을 붙이므로 언어별 글꼴이 저절로 나뉜다. 단위 `lang`은 API에 있다. 한글은 어절로 끊고(`word-break: keep-all`) 줄 높이를 27px로 넓힌다.

## 8. 화면 구조

크기는 시안 값이다(1248 × 720 프레임).

**공통 상단 막대 44px**, `--chrome` 배경. 왼쪽부터 워드마크(강조 700, 16/24, `--brand-ink`, 묶음 목록으로 이동), 버전, 구분선, 묶음 제목, Synthetic data 표시, 빈 공간, 사용자 이름과 부서, 배치 버튼, 언어 버튼, 관리, 로그아웃이다.

**왼쪽 레일(기본)** 72px, `--chrome` 배경. 항목은 60 × 54px이고 아이콘이나 번호 위, 11px 라벨 아래다. 순서는 Overview, Documents, 1 Split, 2 To-Be, 3 Classify, 3 Match, 4 Outputs, Review다. 현재 항목은 `--hl` 번호 칸과 `--chrome-hover` 배경으로 표시한다. 묶음 목록 화면에서는 숨긴다.

**상단 2단** 단계 막대 38px + 선 1px. 항목과 순서는 같고 현재 항목은 번호 칸과 밑줄로 표시한다. 선택해도 굵기를 바꾸지 않는다. 글자 폭이 달라져 옆 탭이 밀리기 때문이다.

**분류: 원문 3단(기본)** 열 232 / 가변 / 392px.

- 왼쪽 목록은 상태 필터 탭, 줄 58px(상태 아이콘, ID, 원문 한 줄). 선택 줄은 왼쪽 3px `--accent` 선과 `--sel-bg`다. 줄과 짝의 관계는 16절의 결정을 따른다.
- 가운데는 용지 막대(문서 번호, 제목, Synthetic data, 쪽, Aa)와 용지(`max-width: 600px`)다. 선택한 단위의 문서를 앞뒤 문맥과 함께 보이고 지금 문장에 밑줄을 긋는다. 줄을 누르면 그 단위를 선택한다. 현재 필터 밖이면 필터를 All로 바꾼다. 머리말과 꼬리말은 흐린 글자로만 구분하고 `Header` 같은 라벨은 용지 안에 넣지 않는다.
- 오른쪽 위부터 ID와 상태와 이전·다음, 보낼 곳(높이 36px, 칸 전체 폭), 주 버튼(높이 38px, 칸 전체 폭), 보조 버튼 한 줄(Edit and confirm E, Hold H, Clear assignment U)이다. 그 아래가 스크롤 영역으로 AI 자리, 새 문장 KO·EN, 변경 종류, 이유, 문장 검사, 확정한 사람을 둔다.
- 보낼 곳과 주 버튼을 붙인 것이 핵심이다. 확정하면 다음 줄로 넘어가므로 반복 동선이 이 구간이다. 앞선 시안 849px에서 45px로 줄었다. 목록을 직접 누를 때는 줄에서 보낼 곳까지 879px로 가장 길다.

**분류: 목록 + 상세** 열 318 / 가변.

- 줄 97px(상태 아이콘, ID, 원문 두 줄, 보낸 곳).
- 오른쪽 위부터 머리 줄, 판단 줄(보낼 곳, 주 버튼, 보조 버튼 순서로 가로), 그 아래 원문과 새 문장을 두 열로 나란히 둔다.
- 보낼 곳에서 주 버튼까지 188px, 줄에서 보낼 곳까지 442px이다.

**쪼개기** 열 232 / 가변 / 392px. 왼쪽 문서 목록, 가운데 용지, 오른쪽 선택 단위 정보와 단축키다. 원문 3단과 같은 칸이라 탭을 옮겨도 용지 좌표가 같다(시안에서 x 324, 폭 510으로 일치 확인). 한/영 짝은 오른쪽 칸의 Pair 항목에서 확인하고 잇는다. 코드는 `ko_en_interleaved` 문서에만 짝을 제안하므로, `ko_en_separate` 문서는 여기서 손으로 잇는다(`POST /documents/{id}/pairs`).

**표 화면** 묶음 목록, 문서, To-Be, 결과물은 `.dense`를 쓴다. 제목 줄에 강조 글꼴 18/24 제목과 주 버튼 하나를 둔다.

**개요** 왼쪽은 제목과 상태, 지금 할 일 카드, 배정 현황(언어별 확정률 큰 숫자, 막대, 건수 표)이다. 오른쪽 340px은 검토 요청 조건, AI 작업, 멤버다.

**짝 맞추기, 검토, 결과물 B·C** 는 시안이 없다. 짝 맞추기는 원문 3단 뼈대로 시작하고, 나머지는 큰 화면이면 사용자에게 시안을 보이고 고르게 한다.

## 9. 판단 흐름

분류 화면의 사람 경로다. 시안에서 동작한다.

1. `Enter`로 보낼 곳 메뉴를 연다. 메뉴에는 To-Be의 칸과 고정 처분(Deleted, Moved to another document)이 나온다. N/A 칸은 보이지만 고를 수 없다. WI는 단계마다 Instruction과 Why로 나뉜다. 시안의 Move는 대상 문서 입력이 없어 비활성이지만 구현에는 넣는다(명세 158행).
2. 고르면 새 문장에 원문이 그대로 들어간다(변경 종류 As is). 아직 점선이다.
3. `Enter`로 확정한다. 다음 미확정 단위로 넘어가고, 확정한 줄은 그 자리에 남는다. 재정렬은 필터를 다시 누를 때만 한다.

단축키는 `J` `K` 이동, `Enter` 주 동작, `E` 고쳐서 확정, `H` 보류, `U` 배정 지우기, `Esc` 메뉴 닫기다. 쪼개기 단축키는 명세를 따른다(`Enter` 확인 후 다음, `J` `K`, `H`, `U` 경계 확인 취소, `S` 나누기, `Ctrl+Z` 편집 취소).

- 주 버튼 라벨은 Choose destination, Confirm, Save and confirm이 같은 칸에 겹쳐 있어 폭과 자리가 변하지 않는다.
- 저장 표시는 판단 영역 오른쪽 아래에 떠서 레이아웃을 밀지 않는다.
- 상태 전이는 명세 §6.8을 따른다. 어떤 상태든 Clear assignment로 Unassigned가 된다. AI 제안으로 되돌리는 길은 없다.
- 미배정에서 보류하는 전이는 명세와 시안에 있지만 지금 API가 받지 않는다. `groups/save`는 `assigned`에 새 문장을 요구하고 `hold`도 같은 검사를 지난다. 16절의 결정을 따른다.
- 삭제, 이동, 중복 배정, 표 구성 변경은 사유가 필수다.
- 시안은 1:1 판단만 그렸다. 나눔, 합침, 중복 배정, 표 구성 변경, 여러 단위 삭제와 이동은 16절의 결정을 따른다. 이미 저장된 `split`, `merged` 결과는 어떤 경우든 표시해야 한다.
- AI 없이도 끝까지 간다. AI 자리에는 안내만 둔다.

## 10. 상태 표현

라벨은 언어와 상관없이 영어다. ko 사전에도 영어 값을 넣고 결정 날짜를 주석으로 남긴다.

| 상태 | 아이콘(lucide) | 모양 |
|---|---|---|
| Unassigned | `circle` | 회색 글자, 테두리 |
| AI suggested | `circle-dashed` | 보라 글자, 틴트, 점선 테두리 |
| Confirmed | `circle-check` | `--accent` 채움에 `--on-accent` 글자 |
| On hold | `circle-pause` | 호박색 글자와 틴트, 테두리 |
| 삭제 | `trash-2` | 원문은 읽히게 한 줄 취소선 |

그 밖의 상태도 같은 의미 색 안에서 나눈다. 시안의 "상태 어휘" 표에 전부 있다.

**칩의 진하기 3단(2026-11-09).** 색 가짓수(회색·파랑·호박·빨강·보라)는 늘리지 않고 무게로 나눈다. 아이콘·선 모양은 그대로 둬서 색만으로 구분하지 않는다. 클래스는 `components.css` `.pill.*`.

| 단 | 모양 | 뜻 | 쓰는 곳 |
|---|---|---|---|
| 테두리 | `none`·`quiet` | 손대지 않음·조용함 | Unassigned, Checked, 모르는 실행 결과 |
| 연한 바탕 | `active`(파랑)·`muted`(회색)·`hold`·`warn`·`danger`·`ai` | 진행·기다림·주의 | In progress, Ready, Succeeded, In review, 경고, 작성자 없음 |
| 꽉 참 | `ok`(파랑)·`done`(회색)·`fail`(빨강) | 확정·끝남·실패 | Confirmed, Review complete, Rejected·Failed(문서·실행 결과) |

| 대상 | 라벨 |
|---|---|
| 묶음 | In progress, In review, Review complete |
| 문서 | Ready, Rejected, Failed |
| 보조 검사 | Checked, Aux check unavailable |
| 한/영 짝 | Suggested(점선), Confirmed |
| AI 작업 | Queued, Running, Done, Failed, Outdated, Cancelled |
| AI 후보 검색 | Search failed, No index, No candidates. 세 상태는 서로 다르게 보인다 |
| Excel 내보내기 | Request in progress, File created, 실패. 명세의 세 단계 중 Confirmed on server는 지금 API에 신호가 없어 쓰지 않는다(14절). 시안의 단계 전환은 타이머다 |

**밑줄은 세 종류다.** 실선은 지금 보는 문장, 점선은 AI 제안, 물결은 누락 의심이다. 컨셉의 실선(확정)과 겹치는 점은 실제로 써 보며 확인한다. 확정 문장은 글자가 흐려져서 구분된다.

- 지금 보는 문장: 2px `--accent` 막대를 줄마다 그린다. `background-image`와 `box-decoration-break: clone`을 쓴다. `text-decoration`은 물결 경고가 쓰므로 비워 둔다.
- 제목 밑줄: `linear-gradient(transparent 88%, var(--accent) 88%)`, `padding-bottom: .16em`. 화면당 하나만 쓰고 표 안에는 쓰지 않는다. 글자에 닿으면 취소선처럼 보인다. 취소선은 삭제 의미라 띄워야 한다.

## 11. 동작 규칙

bpm에서 가져온 규칙과 이 앱 때문에 더한 규칙이다. 시안 맨 아래에 출처까지 적힌 표가 있다.

**튀지 않기**

- 데이터 전에는 최종 모양과 같은 크기의 스켈레톤을 둔다. 150ms 안에 오는 응답은 스켈레톤도 보이지 않는다.
- 다시 불러오는 동안 목록을 비우지 않는다.
- 빈 값도 같은 자리를 차지한다(–와 점선 칩).
- 호버로 높이를 바꾸지 않는다. 호버로 대상을 줄이지 않는다.
- 번갈아 나오는 내용은 같은 칸에 겹친다.
- 폭은 탭이 아니라 모드 단위로 바꾼다.
- 높이 변화는 전환으로 잇고, 첫 측정은 애니메이션 없이 한다.
- 팝오버는 위치를 잰 뒤 띄운다.
- 숫자가 줄을 맞추는 곳은 `tabular-nums`다.
- 강조는 굵기로 하지 않는다. 글자 폭이 달라져 원문 줄바꿈이 밀린다.
- 글꼴 교체로 튀지 않게 미리 불러온다.

**손 덜 옮기기**

- 주 버튼 자리는 단위가 바뀌어도 같다. 영역당 하나다.
- 드롭다운은 트리거에 붙인다.
- 닫기는 mousedown과 Esc다. Esc는 최상위만 닫고 포커스는 연 곳으로 돌아간다.
- 툴팁은 150ms 지연으로 뜨고 네이티브 `title`을 쓰지 않는다.
- 경계에서 뒤집고 화면 안으로 맞춘다.
- 단축키는 버튼 옆에 `kbd`로 적는다.

**다음 일 보이기**

- 상태와 다음 행동을 먼저 둔다. 긴 설명은 도움말로 뺀다.
- 일이 끝나면 조용해진다. 확정 줄은 색을 빼고 색은 처리할 일에만 쓴다.
- 상태는 아이콘, 선 모양, 라벨을 함께 쓴다. 색만으로 구분하지 않는다.
- 사람은 이름을 먼저 쓰고 ID는 보조다.
- 모달은 아이콘, 제목, 대상, 요약 상자로 만든다. `window.confirm`을 쓰지 않는다.

**기타**

- 아이콘 크기는 12, 14, 16, 28이고 선 굵기 1.5다.
- 굵기는 400과 600이다. 강조 글꼴만 예외다. 줄 높이 1은 쓰지 않는다.
- 모든 인터랙티브 요소에 `data-testid`를 붙인다(`rules/frontend/identifiers.md`).
- UI 문구에 긴 대시를 쓰지 않는다. en과 ko 문구는 함께 추가한다.
- 시각 표시는 KST다(`lib/datetime`).
- 추정 쪽은 ≈를 붙인다. 합성 묶음과 문서에는 Synthetic data 표시를 둔다.

## 13. 데이터 메모

- 시드 데모는 합성 묶음 4개다(4번째가 AI 제안 묶음). KO 43단위, EN 55단위로 언어별로 따로 센다.
- 단위 하나는 언어 하나이고 짝이 KO와 EN을 잇는다. 시안은 한 단위에 두 언어가 있는 것처럼 단순화했다. 구현은 `pairs`를 따른다.
- 시드 짝은 96개(묶음당 32개)이고 전부 `suggested`, 전부 1:1이다. 묶음 2 기준 `ko_en_interleaved` 문서에만 있고 `ko_en_separate`와 `en_only` 문서에는 없다.
- `pair_id`는 `/documents/{id}/view`의 `units`와 `/units` 행에 모두 있다(분류 화면은 아직 문서 보기의 짝을 쓴다).
- 짝 저장은 서버가 대신하지 않는다. 같이 저장할 단위를 요청에 명시해서 담는다(명세 317행). 짝 확정은 `POST /documents/{id}/pairs/{pair_id}/confirm`이다.
- ID는 합성 `OLD-1-001`, 실제 `SOP-QC-00005-012` 모양이다. 긴 ID가 들어갈 자리를 잡는다.
- 합성 문장은 중간값 25자, 최대 94자다.
- `doc_version`은 시드에서 비어 있고, 쪽 근거는 `estimated`다.
- `ai_suggested`는 4번째 시드 묶음에만 있다.
- `/documents/{id}/view`가 `blocks`, `units`, `pairs`, `tables`를 준다. `/units`의 `unit_id`로 `/groups/by-unit/{unit_id}`를 부른다.
- 검토 조건은 `/review/readiness`의 `blockers`, 다음 행동은 `next_action`을 쓴다.

## 15. 검증

- **대비는 실제 글자로 잰다.** 토큰 쌍 검사만으로는 부족하다. 시안에서 토큰 표는 전부 통과했는데, 다른 방향의 값이 새어 다크 개요 제목이 대비 1.08로 거의 보이지 않았다. 화면의 글자마다 실제 배경과 대비를 재는 방식이 이걸 잡았고, 저장소에서는 `frontend/scripts/pw-contrast-audit.mjs`가 같은 방식으로 잰다.
- 라이트와 다크를 모두 본다. 기준은 4.5:1, 큰 글자는 3:1이다. 비활성은 제외한다.
- 튐 검사: 확정 전후로 줄 y와 주 버튼 좌표, 폭이 같아야 한다. 탭을 옮겨도 단계 항목 x와 용지 좌표가 같아야 한다.
- 팝업: Esc, 포커스 복귀, 바깥 클릭, 키보드를 시험한다(명세 §12).
- 색약: 시안 G 기준 확정과 보류 ΔE 27.8, 확정과 AI 9.5, 확정과 오류 17.1이다(적색약). 예전 초록 확정색은 보류와 5.9였다. 색을 바꾸면 다시 잰다.
- **Windows에서 본다.** 검증 PC가 Windows다. 지금까지는 Mac 헤드리스 Chrome으로만 봤다. Windows 글자 렌더링, 강조 글꼴 세로 위치, 맑은 고딕과 바탕, Calibri는 아직 보지 못했다.
- 시안의 모든 수치는 1248 × 720 프레임 기준이다.

## 17. 컨셉 세션이 정한 기본값

사용자가 직접 말하지 않고 컨셉 세션이 정해 구현에 쓴 기본값이다. 바꾸려면 사용자와 정한다.

- 원문 글꼴 설정의 범위를 원문으로 봤다. 앱 글자는 바꾸지 않는다.
- 원문 글꼴 기본값을 Pretendard + Arial로 했다.
- 설정을 서버가 아니라 브라우저에 저장한다.
- 상태 표기 영어 고정을 단위 상태뿐 아니라 묶음, 문서, AI 작업, 내보내기까지 넓혔다.
- 밑줄 강조를 제목뿐 아니라 지금 보는 문장까지 적용했다.
- 주 버튼 파랑을 `#036EAE`에서 `#045797`로 어둡게 했다. AI 보라와의 색약 구분 때문이다.
- 쪼개기 열을 원문 3단과 같게 맞췄다. 시안은 목록 + 상세일 때 196 / 가변 / 256이지만 하나로 통일하는 편이 낫다.
- Gmarket Sans는 이름을 바꾼 경량본을 권장했다.
- 묶음 목록이 `/`를 대체한다고 봤다.
- 관리 탭을 1차 뒤로 미뤘다.
- AI 범위를 안내 자리까지로 봤다. 1차 프롬프트의 "AI API 스키마가 main에 들어오면 합쳐서 붙인다"를 따른 것이다.
- 한/영 짝 잇기를 쪼개기 오른쪽 칸에 뒀다.
- Excel 내보내기 표시를 지금 API에 맞춰 두 단계와 실패로 줄였다.
