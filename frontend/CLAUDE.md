# frontend/CLAUDE.md

frontend(Next.js) 세부 구조와 frontend에만 걸리는 체크리스트. 루트 [`CLAUDE.md`](../CLAUDE.md)에서 그대로 옮겨 왔고 이 폴더의 파일을 읽을 때 실린다. 프로젝트 개요·명령·배포 제약·규칙(`rules/`)·양쪽에 걸친 체크리스트(권한·env·거절 코드 문구)는 루트에 있다. 경로 표기는 루트에 있을 때 그대로다 — `src/…`·`public/…`·`app/…` 라우트·`scripts/pw-*.mjs`는 `frontend/` 아래, `docs/…`·`rules/…`는 저장소 루트. 화면이나 검증 스크립트를 건드리기 전에 `docs/lessons/`도 먼저 읽는다(루트 Lessons).

## 핵심 구조

**frontend 핵심:** `src/lib/api.ts` `apiFetch`(인증 헤더, dev 사용자는 요청마다 localStorage에서 읽음) · `api-errors.ts` `humanizeApiError`(상태 코드별 사람 말 문구, 서버 원문은 422 검증 사유에만) · `access.ts` 권한 카탈로그 미러 · `i18n-messages.ts` en/ko 메시지 · `keycloak-login.ts` OIDC 설정 단일 소스(PKCE는 `crypto.subtle`이 있을 때만) · `genId()`·`copyText()`(secure context 우회). localStorage 키 접두는 `sopa.`. SOP 화면: `api-sop.ts`(SOP API 호출·응답 타입), 화면 규칙은 순수 모델에 두고 시험한다 — `paper-model`(원문 용지)·`tobe-draft`(To-Be 초안, 하위 항목은 줄 키에 묶고 단계 번호는 다시 매기지 않는다)·`classify-model`(Assign 줄·보낼 곳·저장 요청 — 새 문장 칸 단위로 AI 나눔·합침 보존, 이미 쓴 문서 문장에 잇는 `link`는 닫힌 관계 묶음 전체를 보낸다. 단 한/영 짝 줄을 한 언어만 이을 때 판단 없는 다른 언어 Unit은 확정 저장에서 빼고(`listLinkLeftovers` — 실으면 서버가 422 `hold_required`) 남는 단위를 같은 저장의 `release_unit_ids`로 보낸다 — 짝은 서버가 그 저장 안에서 풀고(`pair_settle`) 화면은 응답의 `pairs_dissolved`로 줄을 나눈다. 줄은 서버 진행 숫자·검토 조건과 같은 규칙이다(`buildRows`, `backend/CLAUDE.md` 줄 기준 숫자))·`assign-model`(묶음 합치기·함께 확정·New 짝 함께 고르기 `addPartnerTargets`·추천 섞기·추천 고른 표시(짝 포함 비교)·이음 선·그 자리 메뉴 항목·확대/폭 범위)·`match-model`(같은 글자 일괄 확정 나누기). **3단계 Assign 화면**(`app/bundles/[id]/assign`, v0.10.0 — 옛 `/classify`·`/match`는 이리로 넘긴다): Old 원문(Split `Paper` 조각)이 곧 목록이고 옆에 이미 쓴 New 원문을 연다(`components/assign/`). 두 문서 사이 세로선으로 폭, 마우스를 올린 문서만 Ctrl+휠·Ctrl ±로 확대(`lib/use-pane-zoom.ts`, 값은 `lib/assign-view-prefs.ts`가 `sopa.assign.*`에 기억). New 문장 목록·Old 하나의 New 후보는 서버 `app/sop/written.py`(`/written-sentences`·`/units/{id}/new-candidates`, 임베딩 캐시만 읽고 없으면 글자 유사도). 공용 훅·저장소: `bundle-store`(묶음 캐시 — 화면 진입마다 다시 부르고 로그아웃·사용자 전환 때 비운다)·AI 작업 상태는 공용 폴러 `lib/ai-jobs-store.ts`(사용자당 하나, `GET /api/ai/jobs/recent`)가 읽고 규칙은 `ai-jobs-model.ts`, 상단 바 표시는 `components/ai-jobs-indicator.tsx`·`ai-jobs-popover.tsx`(`use-ai-jobs`는 그 묶음의 요청이 바뀔 때 `/ai/status`만 다시 읽는다)·`leave-guard`(미저장 이탈 가드)·`use-loaded`. `ui-prefs`(화면 설정 값 목록)와 `layout.tsx`의 첫 페인트 전 boot 스크립트가 같은 값을 쓴다. **UI 규칙(디자인 기초 문서)**: raw hex는 `src/styles/tokens.css` 밖에서 쓰지 않고, 다크는 토큰만 바꾸며 화면 코드가 테마로 분기하지 않고, 상태 표기는 화면 언어와 상관없이 영어다. **이동·움직임 공통 층**: 앱 안 이동은 `lib/nav-buffer.ts` `navigate()`(0.6초 버퍼, 같은 곳 재클릭·Esc 취소)로 하고 링크 클릭은 `components/nav-host.tsx`가 창 캡처 단계에서 같은 길로 돌린다 — 사람이 고른 이동에 `router.push`를 새로 쓰지 않는다(저장 안 한 변경 가드 `useLeaveGuard`도 이 길에 걸려 있다). 접기·쉬머·폭 모핑·말줄임 툴팁은 `components/ui/motion.tsx`, 긴 목록은 `lib/use-progressive-list.ts`, 목록 자리 바꿈(FLIP — 바뀔 줄만 재고 움직임 줄이기면 바로)은 `components/ui/motion.tsx` `useFlip`(거리는 `lib/flip.ts`), 호버로 드러나는 보조 단추는 `.row-actions`(`styles/motion.css`). 결과물 C의 순서·깊이·표시는 화면에 먼저 얹고(`lib/c-edit-model.ts`) 저장은 한 번에 하나씩 보내며(`lib/c-save-queue.ts`, 의미 확인 체크도 같은 줄) 응답의 그 문서로 맞춘다 — 저장 전 번호 미리 세기 `section-number.ts` `numberLines`는 backend `outputs.number_lines`의 사본이라(저장 응답이 이긴다) 서버 규칙을 바꾸면 함께 고친다. 백엔드에만 있던 묶음 관리·AI 요청·관리 묶음·AI 지침 API는 `lib/api-manage.ts`. Markdown 글(AI 지침)의 읽기 보기는 `components/ui/markdown-view.tsx` 하나를 쓴다(escape 뒤 서식만 태그로 — 원문 HTML을 그대로 넣는 길을 새로 만들지 않는다). **목록·값 고르기 공통 부품**: 읽기 위주 목록은 `components/ui/data-list.tsx` `DataList`(열 정의 하나로 표·밀도 높은 카드, 보기는 `ListViewToggle`·`lib/use-list-view.ts`가 목록마다 `sopa.listView.<key>`에 기억, 남은 폭을 채우는 열은 `grow`)를 쓰고, 값 하나 고르기는 `components/ui/select.tsx` `Select`(떠 있는 목록은 `Menu` listbox, 항목 testid `<testId>-option-<value>`, 스모크는 트리거→항목 클릭)를 쓴다 — 기본 `<select>`를 새로 쓰지 않는다. 추천 목록에서 고르거나 그대로 입력하는 칸은 `components/ui/combobox.tsx` `Combobox`(항목 testid `<testId>-option-<value>`, 입력 그대로 모양(체크박스·라디오·`title` 툴팁)을 쓰지 않는다 — `components/ui/checkbox.tsx` `Checkbox`(숨긴 네이티브 입력 위에 토큰으로 그림)·`tooltip.tsx` `Tooltip`·`info-tip.tsx` `InfoTip`(개념 설명은 본문 대신 (i) 툴팁). 글자 없이 아이콘만 있는 표시는 포인터를 올리거나 키보드 ## 체크리스트 — 같이 움직여야 하는 곳

- **프런트 텍스트:** en·ko 메시지를 한 쌍으로 추가한다(`i18n-messages.test.ts`가 키 집합을 가드). 인터랙티브 요소에는 `data-testid`(`rules/frontend/identifiers.md`).
- **화면·동작·라벨을 바꾸면 사용 설명서도 같은 커밋에서:** `frontend/public/manual/user-manual.md`의 해당 조각을 고치고, 화면 모양이 달라졌으면 그림을 다시 뽑는다(`MANUAL=app node scripts/pw-manual-shots.mjs`, 위 Commands). 설명서는 화면 라벨을 영어 화면 글자 그대로 **굵게** 적는다 — `manual-content.test.ts`가 굵은 영어 글자를 en 문구 사전과 대조하고(라벨을 바꾸면 여기서 걸린다), 권한 키 전부·그림 빠짐과 남음·도움말이 여는 조각·바깥 주소와 IP 없음을 본다. 새 단계나 화면을 더하면 `lib/manual.ts`의 `MANUAL_STAGE_SECTION`·`MANUAL_PAGE_SECTION`에 조각을 잇는다. 머리의 `version`은 서비스 `MAJOR.MINOR`와 같아야 한다(같은 테스트) — MINOR를 올리는 릴리스에서 설명서를 다시 읽고 `version`·`updated`를 함께 올린다. 글과 그림은 로그인 밖에서도 열리는 정적 파일이니 실제 SOP 글자·직원 이름·서버 주소를 넣지 않는다(그림은 합성 데모 DB에서만 찍는다).
