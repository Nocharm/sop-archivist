# 문서 문단 분리 · 문단 엑셀 개선 요청 (2026-11-19)

사용자가 준 요청서(`문단분리_문단엑셀_개선요청.md`, 원본은 사용자 PC)를 사진에서 옮겨 적었다. 뒤의 "분류 메모"는 받은 세션이 붙인 것이다 — 요청서 본문이 기준이고, 메모는 출발점일 뿐이다.

---

## 0. 배경 및 우선순위
- 원본 문서가 매우 복잡하고, 투비(To-Be) 문서도 구성이 좋지 않음
  → 문단 분리 로직과 UI/UX를 확실하게 개선해야 함
- 1차 타겟: 문단 분리 + 문단 엑셀 추출품
- 2차 (앞단 완결 후 고도화): 매핑, 비교 엑셀
  - 실제 작업해 보니 매핑이 매우 복잡하고 참조도 불편함. 개선할 부분이 많은 상태

## 1. 제목-문장 짝
- 현재: 예) 제목 2개, 문장 짝 3개로 나뉜 뒤 아래쪽을 누르면 위쪽이 포커싱됨 → 직관적이지 않음
- 요청: 짝(pair)이라면 순서 변경을 하면서 작업할 수 있어야 하고, 짝 관계가 시각적으로 더 티 나야 함

## 2. 글머리 번호
- 현재: 자유 입력 수준
- 숫자형: 워드처럼 규칙이 잡힌 연속 번호로 처리
- 추출한 값과 달라진 경우: 노트(기록)로 남김
- 점(•), 동그라미(○) 등 dot 타입: 버튼으로 제공
- A-1 등 기타 형식: 별도 타입을 클릭해서 입력
- 해당 모달: 바깥 클릭 또는 ESC로 닫히게 할 것 (현재 끄기가 너무 힘듦)

## 3. 들여쓰기
- 문단 번호(레벨)에 따른 들여쓰기를 5단계까지 시각적으로 차이 나게 할 것

## 4. 삭제/이동 리마크
- 문단 삭제나 이동 시 리마크 입력을 강제하지 말 것
- 사유에는 기본적으로 단순히 "삭제", "이동"으로 기록
- 리마크를 작성한 경우에만 해당 내용으로 대체

## 5. 삭제된 문단 박스 표시
- 목차 박스처럼 비활성화된 느낌으로 표시하고, 내용 자체를 축소해서 보여줄 것
- 표, 그림도 동일하게 적용

## 6. 호버 묶기 동작 방식 변경
- 활성화된 문단 박스 기준, 위/아래 박스 사이 벌어진 공간에 호버할 때만 버튼 노출
- 그 외 영역에서는 노출하지 않음

## 7. 표 행으로 나누기 / 표 벗기기
- "표 행으로 나누기"가 정말 필요한지 검토 → 필요 없으면 헷갈리기만 하니 제거하고 "표 벗기기"만 남길 것
- 벗긴 표 사이 문단의 순서 변경이 가능해야 함 (임의로 순서를 박아 넣은 것이므로)
- 순서 변경 방식 후보 (검토 필요):
  - a. 드래그 앤 드롭으로 순서 변경
  - b. 세로 우선 / 가로 우선 선택 + 열 일괄 합치기
  - c. 벗기기 시 AI로 순서 및 들여쓰기 제안
    - 자체 양식으로 번호를 쓴 경우 → 번호로 처리
    - 열, 값 순서인 경우 → 열에 dot 타입을 넣는 느낌으로
- 결론: 결국 "표로 유지"하거나 "문단 단위로 찢기" 둘 중 하나임

## 8. 함께 벗기기 제거
- 표 벗기기의 "함께 벗기기" 기능은 제외 (더 헷갈리기만 함)

## 9. 붙이기/묶기 반응 속도
- 붙이기나 묶기 반응 자체가 느림 → 개선 필요

## 10. 그림 섹션 분리
- 그림은 문서 기본 보기에서 모두 제외
- 머리말/꼬리말처럼 별도 "그림 섹션"으로 전부 분리
- 그림 섹션에서 삭제 가능하게 할 것

## 11. 1개 보기 시 스페이스 미리보기
- 1개 보기 상태에서 스페이스를 누르면 나오는 엑셀 미리보기 → 문단 엑셀로 표시
- 문단 엑셀에는 섹션 번호 표기 (dot 타입 글머리는 상위 번호를 지정)

## 12. 레퍼런스 타입 범위
- 레퍼런스 타입은 문서 뒤쪽에 "Reference" 섹션이 나온 이후의 문장들로만 한정

## 13. 처리 중 로딩 애니메이션
- 표 벗기기, 합치기, 나누기 등 처리 중 아무 애니메이션이 없어 명령이 전달 안 된 것처럼 보임
- 처리 대기 중 애니메이션 추가 (전반적으로 서버가 느린 경우가 많음)

## 14. REF 제안 처리
- REF 제안은 기본적으로 "제안 확정" 상태로 표시
- 확인 버튼 외에, 언어 필(pill) 옆 REF를 눌러도 확인 처리되게 할 것

## 15. 우측 인스펙터 클릭 효과
- 현재: 우측 인스펙터 바를 누르면 결정 영역으로 날아가는(이동하는) 효과 → 정신 사나움
- 변경: 결정 영역이 쉬머(shimmer)되면서 내용이 바뀌는 효과로 변경

## 16. 우측 인스펙터 사유 3종
- 사유가 3개로 나뉘어 나올 때가 있음 → 왜 이렇게 구성되어 있는지 배경을 찾아서 보고할 것
- 제안: 완벽히 일치하면 "=", 그 외는 모두 "수정"으로 표기 (굳이 3가지로 나눌 필요 없어 보임)

## 기타 공통 요구사항
- 그 외 사용성 개선 항목도 확인할 것
- 문단 엑셀 / 비교 엑셀: 컴퓨터가 추출한 값 중 표면적으로 드러나지 않는 항목은 노출하지 말고 제외
- 사용감 통일:
  - 올드 문서와 뉴 문서의 문단 쪼개기 사용감, 빈 템플릿 문서의 사용감이 매우 다름 → 통일할 것
  - 특히 뉴 문서와 빈 템플릿은 "문단 내용과 순서의 편집 가능 여부" 외에는 전부 동일해야 함 (현재 너무 다름)
- 원칙: 제로베이스에서 다시 설계. 사용자 경험의 통일성과 직관성이 가장 중요하고, 복잡도를 낮추는 것이 목적
- 체감: "반응이 없다", "답답하다"는 느낌을 최소화할 것

## 시안 1 피드백 (2026-11-19, https://claude.ai/artifact/EjnLRVJFB7RajXZ5TiwyH2)

- **1번의 실제 경우**: 문장 1~6에서 1↔4, 2↔5, 3↔6이 짝(떨어진 짝)이라 4를 누르면 1, 5를 누르면 2가 잡혔다("제목으로"를 누르면 123 · 456 두 문단으로 돌아온다). 원인은 화면이 짝 한 줄을 고르고 첫 문장을 보이는 것. → **누른 박스 하나를 고른다.** 결정 칸 Shape도 누른 박스 먼저, 보낼 곳 · 확정은 짝 전체.
- **떨어진 짝 표시(한 · 영 따로 쓴 문서 포함)**: 원래 자리를 살린다(위로 모아 보이지 않는다). 오른쪽 짝 아이콘 + 고른 박스 아래 흐린 한 줄(짝 글 · 자리)만, 누르면 짝의 원래 자리로. 위 · 아래 어느 쪽을 골라도 같다.
- **끌기**: 같은 문서 안 박스를 끌어 다른 박스에 놓아 짝 맺기(따로 쓴 문서에도), 카드 안 순서도 끌기. 벗긴 표 안 순서 바꾸기는 7번(시안 2).
- **3번**: 들여쓰기 폭은 지금이 좋다. 문제는 4단계부터 번호가 "5.2.1…"로 잘리는 것(번호 칸 폭이 단계마다 고정 — `PILL_WIDTH_BY_LEVEL`). → 같은 단계의 가장 긴 번호가 다 들어가게 그 단계 칸만 넓힌다.
- **5번**: 삭제 박스는 흐린 한 줄로 접고 DELETED 태그만 반투명 빨강.
- **9 · 13번**: 누르는 즉시 로딩 애니메이션(지연 없이).
- 남은 확인: 15번(결정 칸 쉬머) · 바탕(상태 한 곳). 그 뒤 시안 2.
