# Assign 긴 문서 끊김 — 설계 (1.2.0 피드백 8번)

> 상태: 스텝 1(v1.1.27)·2(v1.1.28)·3(v1.1.29) 구현됨, 스텝 4는 사용자가 :4444에서 실제 문서로 본 뒤 정한다(2026-11-17). 프런트만 — API·자료 구조·권한·Alembic은 건드리지 않는다.

## 문제

실제 회사 문서를 개발 스택(:4444)에 올리자 Assign에서 **스크롤·호버·초점 바꾸기(고르기)마다 프레임이 떨어진다**(사용자, 2026-11-17). 문단 수는 모른다. 처음 생각한 처방은 "화면 밖 문단 가상화"였다.

## 잰 것

`frontend/scripts/pw-perf-assign.mjs`로 쟀다. 운영 빌드(`next build` → `next start`)를 쓰고, CPU를 4배 느리게 해서 사내 PC에 가깝게 맞췄다. 자료는 극단 자료 묶음 W1의 문서 셋이다(합성).

| 문서 | 문단 | DOM 노드 | 호버 1회 | 스크롤 1프레임 p50 | 누르기(이벤트) |
|---|---|---|---|---|---|
| 작은 문서 | 51 | 1.7천 | — | 17ms | 90ms |
| BIG (`OLD-90`) | 372 | 7.5천 | 23ms | 17~28ms | 140ms |
| huge pair view | 1,323 | 2.9만 | 56~69ms | 60~120ms | 400~700ms |

가만히 있을 때(6초)는 긴 작업이 없다. 배경 폴러·관찰자가 그리기를 깨우는 일은 없었다.

## 원인 (주입해 잰 것)

1. **문단 사이 틈(`.strip-gap`)이 화면 밖에서도 그려진다.** 문단 줄(`.strip-row`)은 이미 `content-visibility: auto`였다. 그런데 문단 사이 틈 1,322개는 빠져 있었다. 틈마다 합치기 단추와 lucide 아이콘이 들어 있다. 그래서 스크롤·호버 때마다 브라우저가 배치·칠하기·히트 테스트를 문서 전체에 다시 했다. 1,323문단 문서에서 이 틈에만 `content-visibility`를 주입하자 호버가 69→20ms, 스크롤이 123→40ms로 줄었다. 진짜 가상화(220줄만 DOM에 남김)는 호버 17ms, 스크롤 25ms였다. 가상화로 얻을 효과의 대부분이 CSS 한 줄로 나온다.
2. **연결선(`LinkLines`)이 그릴 때마다 문서 전체를 뒤진다.** 화면이 다시 그려질 때·스크롤·호버가 바뀔 때마다 `measure`가 돈다. 이때 `updateChipDirections`(칩마다 `findOldStrip` = 문서 전체 `querySelector`)와 `updateBadgeDirections`(배지마다 `getBoundingClientRect`와 `dataset` 쓰기를 번갈아 함)가 돈다. 호버 프로파일에서 JS 시간 대부분이 여기였다.
3. **누르기(고르기)는 `Paper`가 모든 줄을 다시 그린다.** `renderRows`·`renderCard`·`renderRow`가 컴포넌트가 아니라 함수 호출이라 React가 바뀌지 않은 줄을 건너뛰지 못한다. 그래서 줄 220개만 DOM에 남겨도 누르기는 300ms 그대로였다. DOM이 아니라 React 쪽 비용이라는 뜻이다. React Compiler가 꺼져 있어 Assign 페이지가 `Paper`에 넘기는 콜백·집합 22개가 그릴 때마다 새로 생기고, 누르기 한 번에 `Paper`가 세 번 그려진다(스텝 2 때 잰 것) — 줄마다 "받은 값이 같으면 건너뛰기"는 페이지를 크게 고치지 않으면 걸리지 않는다.

스텝 4를 미루는 까닭: 가상화하면 화면 밖 줄이 DOM에 없다. 그러면 브라우저 찾기(Ctrl+F), `scrollIntoView`로 줄 데려오기, 출처 칩·연결 배지의 위·아래 방향 표시, 끌어서 놓을 자리 찾기, 키보드로 다음 줄 가기가 모두 DOM에 줄이 있다고 가정한 데서 다시 짜야 한다. 줄을 전부 그린다고 가정한 스모크도 많다. 스텝 1의 주입 실험에서 가상화가 더 주는 몫은 호버 3ms·스크롤 15ms 남짓이었다.

## 지키는 것

- `content-visibility: auto`는 칠하기를 상자 안으로 자르고(paint containment) 쌓임 맥락을 만든다. 상자 밖으로 나오는 표시(올림 자리·알약·그림자)가 있으면 `overflow-clip-margin`으로 자르는 선을 민다. 고칠 때마다 변경 전·후 같은 자리를 찍어 비교한다(스텝 1: 틈 올림 알약 동일, 틈 위아래 8px 호버 동일).
- 스크롤 중 화면 튐은 "보던 줄이 굴린 양만큼 움직였나"로 잰다 — 스크롤 고정이 `scrollTop`을 고치므로 `scrollTop` 차이와 비교하면 고정이 잘 된 것을 튐으로 센다.
- 숫자는 개발 빌드가 아니라 운영 빌드로 잰다(개발 빌드의 누르기는 운영 빌드의 5배 남짓이다). 기기 부하로 숫자가 흔들리므로 처방 전·후를 같은 실행 안에서 `INJECT`로 비교한다.
