# 화면 개편 — T/F 첫 실사용 전 피드백 반영 설계

- 날짜: 2026-11-09 · 대상 버전: v0.9.0 (MINOR, 사용자에게 보이는 변경)
- 목업(승인본): `docs/design/2026-11-09-ui-revamp-mocks/` — `mock-1-shell.html`(공통 틀) · `mock-2-overview.html`(Bundle 개요) · `mock-3-documents.html`(문서) · `mock-4-split.html`(Split). 브라우저로 열어 호버·클릭으로 동작을 본다. 목업은 앱 토큰(`tokens.css`)을 옮겨 그린 것이라 색·간격은 토큰 이름을 그대로 따른다.

## 1. 왜

SOP Restructuring T/F가 실제 SOP로 처음 써 보기 직전이다. 사용자(제품 책임자)가 화면을 단계 순서대로 직접 써 보며 31개 항목과 추가 지적을 냈다. 목표는 **처음 쓰는 사람이 설명 없이 다음 행동을 알 수 있는 화면**이다. 운영 서버(v0.8.0)에서 검토자를 지정하지 못하는 버그도 같은 경로에서 드러났다.

성공 기준: 사용자가 같은 흐름(로그인 → 새 Bundle → 문서 업로드 → Split → 검토 요청)을 다시 밟았을 때 목업과 다른 곳이 없고, 막히는 곳이 없다.

## 2. 범위

**하는 것**: 아래 §4~§8의 항목 전부. 한 브랜치(`feat/ui-feedback-revamp`)에서 하고 끝나면 v0.9.0으로 한 번에 재배포한다(사용자 결정 — 버그 수정도 따로 핫픽스하지 않는다).

**하지 않는 것**
- 분류·짝 맞추기·To-Be·결과물 화면의 기능 변경. 이 화면들은 공통 부품(빈 화면, 드롭다운 단추, 삭제 단추, 라벨 원칙)이 바뀌는 만큼만 따라 바뀐다.
- AI 제안의 정확도 주장. 문서 정보 AI 제안(§6.3)은 배선만 하고 합성 시험으로 검증한다.
- DOCX 원본 모양 그대로의 미리보기(§6.5).

**실패로 보는 것**: 목업은 맞췄는데 기존 동작(키보드 흐름, 미저장 이탈 가드, 권한 차등, 라이트·다크, 대비 4.5:1, 좁은 화면)이 깨지는 것.

## 3. 공통 원칙

### 3.1 라벨 (사용자 지적: "다시 짤 옛 SOP" 같은 말이 AI스럽다)
- 단추·칸·제목은 **짧은 명사형**(업로드, 미리보기, 짝 맞춤, 경계 확인). 설명은 꼭 필요할 때만 한 줄, 문장형 풀이("~을 정합니다", "~하는 곳")를 라벨에 쓰지 않는다.
- 설명이 필요한 개념(한/영 짝, 합치기, 누락 의심 등)은 본문 문단 대신 **이름 옆 (i) 정보 아이콘 + 호버 툴팁**(§3.5)으로 옮긴다.
- 직역투 금지: "번호 넣기", "판 넣기" 대신 빈 칸 placeholder "문서 번호", "버전". "판"이라는 말은 "버전"으로 바꾼다.
- 같은 동작은 같은 말: "올리기"와 "업로드"는 **업로드**로 통일한다.
- **도메인 용어는 화면 언어와 상관없이 영어**: Bundle · Old · New · Unit(지금 한국어 화면의 "묶음·옛·새·단위"). 사용자가 말한 "블록"은 화면에 없는 말이라 "단위"로 읽었다(내 판단). 상태 표기가 이미 영어인 규칙(디자인 기초 문서)과 같은 방향이다.
- 적용 범위는 **화면 문구(i18n)와 화면의 거절 문구(`rule.*`)**까지다. Excel·흐름도·결과물에 찍히는 글자(`output_labels.py`)는 산출물 양식이라 바꾸지 않는다(내 판단).
- 작업: `i18n-messages.ts`의 ko 문구 전체(영어 문구도 같은 원칙으로)를 한 번 훑어 고친다. 키는 그대로 두고 값만 바꾼다. 맥(Cmd) 안내 문구는 없앤다.

### 3.2 빈 화면 (5·15번)
모든 화면에서 내용이 없으면 한 줄 문장 대신 **가운데 박스**: 아이콘 + 짧은 제목("Bundle 없음") + 한 줄 안내 + (할 수 있으면) 다음 행동 단추. 공통 부품 `EmptyState` 하나를 만들어 묶음 목록·문서·To-Be·Split·분류·짝 맞추기·결과물·검토·관리 표가 모두 쓴다. `data-testid`는 화면마다 `<surface>-empty`.

### 3.3 아이콘 단추와 모핑 (10·11번)
- **삭제류**: 평소 휴지통 아이콘만 보이고, 호버·키보드 포커스 때 위험색(danger) 바탕으로 바뀌며 라벨이 오른쪽으로 슬라이드해 길어진다(마우스를 의도적으로 올려야 라벨이 보인다). 확인 모달 안의 최종 삭제 단추는 처음부터 라벨을 보인다. 지금 호버 때 글자가 안 보이는 대비 문제도 이것으로 없앤다.
- **취소** 단추에는 X 아이콘, 그 밖의 위험 동작에도 맞는 아이콘을 붙인다.
- **시작**(다음 할 일): 오른쪽 화살표를 쓰지 않는다. 재생(▶) 아이콘이 평소 숨어 있다가 호버 때 단추가 넓어지며 함께 나온다.
- 기존 `components/ui/motion.tsx`의 폭 모핑(`MorphWidth`)과 같은 움직임 토큰(`--dur-*`, `--ease-*`)을 쓰고 `prefers-reduced-motion`에서 끈다. 공통 부품(예: `MorphButton`)으로 묶는다.

### 3.4 드롭다운 (17번 + 추가)
- **닫힌 단추(공통 `Select` 트리거)**: 평소 라벨이 가운데. 호버·포커스 때 라벨이 왼쪽으로 조금 밀리고 오른쪽에 아래 쉐브론이 나타난다. 펼친 목록 항목은 왼쪽 정렬 그대로(내 판단).
- **목록 행 호버**: accent를 섞은 바탕 + 왼쪽 2px 막대. 막대 쪽 모서리는 둥글리지 않는다(둥근 막대는 "손톱 같다" — 사용자). 라이트·다크 모두, 사용자 메뉴에도 같은 규칙. 다크에서 지금 호버가 거의 안 보이는 것이 고칠 대상이다.

### 3.5 정보 툴팁
(i) 아이콘(`Info`, 14px, `ink-4`)에 호버·포커스하면 설명 상자. 기존 `components/ui/tooltip`을 쓰거나 넓혀서 화면 가장자리에서 잘리지 않게 위치를 잡는다. 키보드로 닿을 수 있어야 한다(`tabindex=0`, `aria-describedby`).

### 3.6 최소 여백 (3번)
창이 좁아져도 본문 박스 양옆으로 회색 바탕이 12~16px 남는다. `AppShell`의 `.page-wrap`에 최소 좌우 여백을 건다.

### 3.7 브라우저 기본 모양 금지 (사용자 지시)
체크박스·라디오·툴팁(`title` 속성)·숫자 입력 화살표·스크롤바 등 브라우저 기본 모양을 화면에 쓰지 않는다. 모두 토큰(`tokens.css`)으로 그린 공통 부품을 쓴다: `Checkbox`(네모, 체크 시 accent 채움), 선택지 카드(§6.1), `Tooltip`(§3.5), 버전 단추(§6.4). 지금 코드에 `type="checkbox"`·`type="radio"`·`title=`이 40여 곳 있으니 전부 공통 부품으로 바꾼다(접근성 속성은 유지 — 숨긴 네이티브 입력 위에 그리는 방식이면 키보드·스크린리더가 그대로 동작한다). 색·반지름·간격·움직임 값은 토큰만 쓰고 raw 값은 `tokens.css` 밖에 두지 않는다(기존 규칙 재확인).

### 3.8 토스트 (사용자 지시, bpm `components/toast-stack.tsx` 참고)
- 자리: 오른쪽 아래가 아니라 **화면 오른쪽 위, 상단 바 바로 아래**.
- 들어올 때 **위에서 아래로** 내려오며 나타나고, 유지(약 2.5초) 뒤 **오른쪽으로** 미끄러져 사라진다.
- 여러 개면 새 것이 위에 쌓이고 오래된 것부터 차례로 빠진다. 하나가 빠질 때 남은 토스트가 **툭 튀지 않고 매끄럽게** 자리를 메운다(높이 접기 또는 FLIP). 오류 토스트는 오류 아이콘 + 왼쪽 위험색 막대.
- 기존 `components/ui/toast.tsx`의 `showToast` 호출부는 그대로 두고 표시 부품만 바꾼다. `prefers-reduced-motion`에서는 움직임 없이 나타나고 사라진다.

## 4. 상단 바와 로그인 (1·2번, mock-1)

- 이름 단추 하나(사람 아이콘 + 이름 + 소속, 이니셜 원은 쓰지 않는다)가 드롭다운을 연다. 항목: **내 계정**(`/account`), **관리**(지금 톱니 단추가 여는 `/admin` — 권한이 있을 때만), **레이아웃** ▸(하위 메뉴: 이동 = 왼쪽 레일/상단 탭, 분류 = 원문 3단/목록+상세, 테마 = 밝게/어둡게, 항목마다 아이콘, 현재 값 체크), 구분선, **로그아웃**(위험색), 맨 아래 작게 **마지막 로그인 시각**.
- 레이아웃 하위 메뉴는 호버로 열리고(키보드는 → 키), **오른쪽에 자리가 없으면 왼쪽으로 뒤집혀** 열린다(열 때 측정).
- 지금 상단 바에 따로 있는 레이아웃·관리·로그아웃 단추와 언어 단추는 이 메뉴와 아래 토글로 옮기고 바에서 뺀다. 개발 모드 사용자 전환 칸은 그대로 둔다.
- **언어 토글**: 네모난 두 칸 스위치 `EN | KO`(현재 값 채움). 앱에서는 이름 단추 오른쪽, 로그인 화면에서는 로그인 박스 오른쪽 위.
- **마지막 로그인**: 서버가 로그인을 기록하지 않으니 새로 남긴다(§9.4).

## 5. Bundle 목록과 개요 (4·6·7·8·9·12·13·14번, mock-2)

### 5.1 바로 생성 (7번)
- "New bundle"을 누르면 이름을 묻는 모달 없이 곧바로 만들고 개요로 들어간다. 이름 대신 **임시 순차 코드** `BND-0013`이 제목 자리에 크게 보이고, 이름은 그 옆 연필 단추로 나중에 붙인다(빈 이름 허용).
- 코드는 저장소 전체에서 한 줄로 이어지는 번호다(사용자 확인). 구현은 §9.1.
- 시험용(synthetic) 표시처럼 지금 생성 모달에서 받던 값은 개요의 `…` 메뉴로 옮긴다(내 판단 — 생성 때 꼭 받아야 할 값이 아니다). 이를 위해 Bundle 수정 API(`BundleUpdateIn`)가 이 값을 받게 한다.

### 5.2 개요 화면
- **제목 줄**: `BND-0013`(고정폭, 크게) + 이름(연필로 편집) + 상태·역할 칩.
- **설명 칸**(8번): 크기 조절 가능, 높이는 최소 64px·최대 200px.
- **다음 할 일 카드**(9번): 왼쪽에 할 일 종류별 아이콘 배지(업로드, 문서 고치기, To-Be, 분류, 경고, 사유, 의미 확인, 검토자 추가, 검토 요청, 검토 대기, 완료). 화면이 열릴 때 아이콘 애니메이션을 **한 번** 재생하고 멈춘다(정지 상태가 완성된 그림). 다음 할 일이 "검토자 추가"면 시작 단추가 멤버 관리 모달을 연다(지금은 단추가 없다).
- **오른쪽 열**(12번): 섹션마다 따로 박스 — Review request · AI job · Members · Activity.
  - **Review request**: 조건을 카드로. **Fail을 위, Pass를 아래**로 나누고, 각 묶음은 3개까지 보이며 나머지는 "N개 더 보기"로 펼친다. 머리에 통과 수 `2 / 7`.
  - **Activity**: 최근 10개, 사건 종류별 아이콘(이름 변경 연필, AI 별, 멤버, 만듦, 삭제 등). 줄을 누르면 **간단한 설명 모달**(누가·언제·무엇, 바뀐 값이 있으면 전/후). 아래 "모두 보기"는 History 화면으로.
- **개요 아이콘**(13번): 격자 대신 계기판(gauge).
- **단계 잠금**(14번): 문서가 하나도 없으면 단계 레일에서 Split·분류·짝 맞추기·결과물·Review가 흐리게 잠긴다(눌러도 이동하지 않고 툴팁으로 이유). **To-Be는 열어 둔다** — Excel 가져오기로 문서보다 먼저 채울 수 있다(사용자 결정). 주소로 직접 들어오면 그 화면의 빈 화면(§3.2)이 업로드로 안내한다.

### 5.3 History (7번)
- 단계 레일 **맨 아래**에 History 항목(내 판단: "묶음 내 가장 아래 히스토리 섹션"을 이렇게 읽었고 사용자가 2부 목업을 승인했다).
- 화면: 사건 표(시각·종류·내용·누가) + 종류 칩 필터(전체/Bundle/문서/판단/AI/검토). 이름 변경은 "전 → 후"를 보여 준다. 새 사건만 전/후가 있고 지난 사건은 종류만 보인다(§9.2).
- 지금 개요의 "Show all 15" 펼치기는 이 화면으로 대체한다.

### 5.4 목록 상단 (4번)
보기 전환(표/카드) 단추에 손가락 포인터와 더 진한 호버 바탕.

## 6. 문서 (16·18·19·20·21·22번, mock-3)

### 6.1 업로드 모달 (16번)
- 무엇을 올리는지는 라디오 대신 **좌우 두 칸의 네모 카드**(Old SOP / New SOP · WI). 창이 좁아도 위아래로 쌓지 않고 늘 나란히(카드 안 내용만 줄어든다).
- 카드 라벨은 짧게: "Old SOP · 쪼개서 새 구조로 배정", "New SOP · WI · Old Unit과 짝 맞춤".
- 지금 New 쪽에서 받는 종류·상위 SOP 번호 칸은 그대로 둔다.

### 6.2 파일별 행과 제안 값 (18번)
- 파일마다 한 줄: 파일 이름 · 문서 번호 · 버전 · 언어 배치. 값이 자동으로 채워졌으면 칸 오른쪽 작은 표로 출처를 보인다(**파일명** / **본문** / **AI**). 사람이 고치면 표는 사라진다. 출처 표는 저장하지 않는다(그 모달 안에서만 의미가 있다 — 내 판단).
- 업로드는 지금처럼 파일마다 즉시 읽는다. 행은 업로드 응답이 오면 서버가 채운 값으로 갱신되고, 사람이 고친 값은 문서 PATCH로 저장한다.

### 6.3 제안 순서 (사용자 승인)
1. **규칙**: 파일 이름(`filename.parse_file_name`, 지금도 doc_code·version을 채운다) → 본문 첫 장 머리글에서 "Doc No.", "문서번호", "Version", "버전", "Rev." 자리 → 언어 배치는 추출한 줄의 한·영 비율과 순서(번갈아/나란히/한쪽만).
2. **AI**: 규칙이 비운 **문서 번호·버전**만, AI가 켜져 있을 때만 묻는다. AI 제안 층의 `load/compute/apply` 계약을 따르는 새 작업 종류로 넣는다(CLAUDE.md "AI 제안 층 불변식"). AI가 꺼지거나 실패하면 칸은 빈 채로 남고 사람 경로는 그대로다.
- **AI 값은 제안으로만 둔다**(불변식 "AI는 제안만 한다", 내 판단): 문서 행에 바로 쓰지 않고 제안 행으로 남기며, 문서 목록의 빈 칸에 흐린 글씨 + `AI` 표로 보여 준다. 사람이 누르면(또는 Enter) 그 값이 문서 PATCH로 저장된다. 그래서 New 문서의 번호가 To-Be 줄 번호를 바꾸는 PATCH 경로(`rename_match_doc`)도 사람의 저장으로만 돈다.
- 규칙 값은 업로드 때 서버가 **비어 있는 칸만** 채운다(사람이 넣은 값을 덮지 않는다).
- **언어 배치**는 규칙으로만 정한다: 추출 직후, Unit을 만들기 전(`units.build_unit_drafts`가 배치로 Unit 언어를 정하므로)에 추출한 줄의 글자 종류 비율과 순서로 정한다. 지금은 기본값 `ko_en_interleaved`로 시작하니 "빈 칸"이 아니라 "업로드 때 한 번 탐지"다. 사람이 업로드 뒤 배치를 바꿀 때의 서버 동작은 지금 그대로 둔다(이번 범위 밖). AI는 배치를 채우지 않는다.

### 6.4 문서 목록
- **구분**: `Old` / `New`(영어 고정).
- **문서 번호**(19번): `SOP-CDO-111334`가 잘리지 않는 폭을 표·카드 모두 늘 잡는다(고정폭 15자 이상).
- **버전**(18·21번): 라벨 "버전". 숫자와 점만 받는다. 오른쪽 위/아래 단추: 소수점 아래가 0이면 앞자리가 움직이고(1.0 ↔ 2.0, 최소 1.0), 0이 아니면 뒷자리가 움직인다(2.9 → 2.10). 칸 **바깥** 오른쪽에 호버 때만 x가 나타나 비운다. 빈 칸 placeholder "버전". 저장 값은 지금처럼 글자다(서버 검증 변경 없음, 규칙은 화면 입력에만).
- **제목**(22번): 호버하면 옆에 연필 → 제자리 편집. 제목 자체를 누르면 그 문서를 연 Split 화면으로 들어간다.
- **언어 배치**(18번): 드롭다운 값에 작은 그림(파랑 = 한국어, 초록 = 영어 칸 배치)과 짧은 말("한영 교차", "한영 분리", "영어만", "한국어만" — 저장 값 `ko_en_interleaved`/`ko_en_separate`/`en_only`/`ko_only`. 목업의 "한영 나란히"는 "한영 분리"로 읽는다).
- **줄 끝 단추**(20번): 미리보기(눈) · 내려받기 · 지우기(휴지통) 순서, 모두 §3.3 모핑.

### 6.5 미리보기 (20번)
앱이 추출한 글의 첫 20줄을 작은 창(종이 모양, 아래로 흐려짐)으로 보이고 "Split 열기"로 이어진다. 원본 파일 모양 재현은 하지 않는다(무겁고 새 외부 라이브러리가 필요). 데이터는 기존 `GET …/documents/{id}/view`로 충분한지, 큰 문서 때문에 앞부분만 주는 가벼운 응답이 필요한지는 빌더가 정한다.

## 7. Split (23~31번, mock-4)

### 7.1 종이
- **경계 확인한 Unit은 잘린 종이 조각**(24번): 위아래에 얇은 틈(7px)을 두고 조각 테두리를 닫는다. 조각 안쪽 위아래 여백을 줄여 전체 길이는 지금과 거의 같게 한다. 확인 전 Unit은 한 장의 종이로 이어진다.
- **틈 호버 = 합치기**(24번): 틈에 마우스를 올리면 점선과 "위아래 합치기" 단추. 바로 위아래 두 Unit만 합친다(기존 합치기 편집을 그대로 부른다). 떨어진 Unit을 Ctrl+클릭으로 합치는 기능은 유지한다.
- **선택 표시**(25번): 밑줄 대신 **글자 영역의 가장 바깥 윤곽 하나**를 테두리로. 여러 줄이어도 줄 사이 선이 없다. 구현 힌트: `Range.getClientRects()`로 줄 상자를 모아 오른쪽 가장자리를 따라 내려갔다 왼쪽을 따라 올라오는 SVG 경로를 종이 위에 겹친다(목업 `drawSelection`). 창 크기·글꼴 설정이 바뀌면 다시 그린다.
- **글자색**: 확인한 Unit은 조금 흐리게, 확인 전은 진하게.

### 7.2 표시 (26번, 사용자 확인: 표시할 수 있는 정보는 같이 보인다)
- **문단 앞 = 글자 태그**: 언어 `KO`/`EN`, 보류 `H`. 둘이 겹치면 한 태그를 **사선으로 쪼개** 함께 보인다(왼쪽 언어, 오른쪽 보류).
- **종이 오른쪽 끝 = 아이콘**: 경계 확인, 한/영 짝, 나눔·합침으로 생긴 Unit, **분류 확정**, **AI 제안 있음**. 분류 확정·AI 제안·보류는 이미 `ViewUnitOut.status`(커버 상태 `confirmed`/`ai_suggested`/`on_hold`/`unassigned`)로 온다 — 새 필드 없이 이 값을 그린다. 나눔·합침 출처는 지금 응답에 없다(§9.5).
- 왼쪽 문서 목록 아래에 범례(앞·태그 / 끝·아이콘).

### 7.3 고르기·확인·나누기
- **첫 클릭**(31번): Unit을 고르고, 문장 끝에 **작은 확인 단추**가 튀어나온다 — 앱 단추(primary) 모양 그대로, 글자 높이에 맞춘 크기(목업 19px). 평소 체크 아이콘만, 호버 때 "경계 확인" 라벨로 길어진다. Enter와 같은 동작(확인 후 다음 Unit으로).
- **고른 Unit을 다시 한 번 클릭**: 아무것도 나누지 않는다(30번 — 지금은 이것이 나눌 선을 놓는다).
- **더블클릭**(30번): 그 자리에 나눌 선을 놓고 선 바로 아래에 "여기서 나누기 S / 취소 Esc" 팝업. 브라우저 기본 단어 선택은 막는다. 끌어 고르기로 새 Unit 만들기(carve)는 그대로.
- **키보드**(27번): ↑/↓도 K/J와 같다(입력 칸·메뉴·모달이 열려 있으면 무시하는 기존 규칙 유지).
- **스크롤**(29번): 고른 Unit이 화면 위·아래 가장자리 쪽으로 가면 화면 가운데쯤 오도록 스크롤한다(지금은 `block: "nearest"`라 맨 아래에 붙는다).

### 7.4 오른쪽 칸
- **넘침**(23번): 긴 글(일련번호, 긴 영어 낱말)은 칸 폭 안에서 줄을 바꾼다. 가로 스크롤이 생기지 않는다.
- **상태 칩**(28번): 확인 전 = 노란 테두리 칩(빈 원), 확인함 = 파란 채운 칩(체크). 색과 모양을 함께 바꾼다.
- **설명 문단 → 정보 툴팁**: 한/영 짝, 합치기, 누락 의심 등의 설명 문단을 (i) 툴팁으로(§3.5). 맥 안내 문구 삭제.

## 8. 사람 고르기 피커 (버그 + 개편)

### 8.1 버그 (운영 v0.8.0에서 재현, 이 브랜치에 수정 포함)
멤버 관리에서 이름을 검색하고 눌러도 목록에 들어가지 않고 저장이 꺼져 있었다. 원인: 실제 HR 디렉터리의 긴 부서 경로가 피커 칸을 옆으로 넓혀 "추가" 단추가 칸 밖으로 잘렸다(로컬 데모 직원은 부서명이 짧아 안 보였다). `SubjectPicker` 바깥 칸에 `min-w-0`을 넣어 고쳤다(긴 부서 30명·1366×768로 전후 재현 확인). 개편 뒤에도 이 조건(긴 경로, 좁은 모달)을 스모크에 넣는다.

### 8.2 공통 피커 (bpm `principal-picker`·`lib/search.ts` 참고)
- 직원 목록을 한 번 받아 모듈 캐시에 두고 브라우저에서 순위를 매긴다. 지금 `/api/directory`는 50명 상한이라 전체를 주는 길이 필요하다(§9.3).
- **검색 순위**: 정확 일치 > 앞부분 일치 > 단어 시작 > 중간 일치 > 초성 > 로마자 > 띄엄띄엄 일치. 같은 순위면 이름 > 한글 이름 > 아이디 순으로 맞은 필드, 그다음 일치 위치가 앞인 쪽, 필드가 짧은 쪽. 사람은 부서명으로 찾지 않는다(부서명이 같은 사람들이 결과를 채운다).
- **검색어가 비었을 때**: bpm은 내 상위 부서장 체인을 먼저 보이지만 이 앱의 HR 데이터에는 부서장 정보가 없다. 대신 **내 부서 → 상위 부서 체인 순서의 같은 조직 사람 → 나머지**(내 판단).
- **무한 스크롤**: 25명씩 그리고 목록 끝에 닿으면 다음 25명을 이어 붙인다(IntersectionObserver 센티널). 검색어가 바뀌면 처음으로.
- 긴 부서 경로는 말줄임 + 툴팁. 피커 하나를 멤버 관리·권한 부여·유효 권한 조회가 함께 쓴다.

## 9. 서버 변경

### 9.1 Bundle 코드와 빈 이름
- 코드 `BND-{id:04d}` — Bundle id에서 만든다(새 열·순번 표 없이 저장소 전체 순차, 지운 번호는 비어 남는다). 10000번째부터는 자릿수가 늘어난다. API 응답에 `code`를 더해 프런트가 형식을 다시 만들지 않는다.
- 생성 입력에서 `title`을 선택으로(빈 문자열 허용). 목록·Excel·결과물 등 제목을 쓰는 곳은 이름이 비면 코드를 보인다.

### 9.2 사건의 전/후 값
`bundle_events`에 바뀐 값을 담을 열(JSON, 선택)을 더하고(Alembic `0008`), 이름·설명 변경과 멤버 변경부터 전/후를 남긴다. 원문 SOP 글자는 담지 않는다(원문은 로그·기록에 남기지 않는 규칙). 사건 목록 API는 History 화면을 위해 더 오래된 쪽으로 넘겨 보는 길(커서)이 필요하다 — 지금은 최근 500개 상한.

### 9.3 디렉터리 전체 조회
피커가 쓸 전체 재직자 목록(이름·한글 이름·아이디·부서 경로·부서 코드). 인증된 사용자 누구나(지금 `/api/directory`와 같은 공개 범위). AI 페이로드가 아니므로 실명 규칙과는 무관하다.

### 9.4 마지막 로그인
로그인을 서버에 기록한다(직원별 마지막 로그인 시각, `/api/me`가 돌려준다). 메뉴의 "마지막 로그인"은 **지금 세션 바로 전의 로그인** 시각이다(내 판단 — 지금 세션 시작 시각은 본인이 안다). 기록 시점(토큰 첫 사용, 새로고침마다 갱신하지 않기)은 빌더가 정한다.

### 9.5 나눔·합침 출처
Split 오른쪽 끝 "나눔·합침" 아이콘을 위해 Unit이 사람 편집으로 생겼는지 알아야 한다. 편집 기록에서 끌어낼 수 있으면 그렇게, 아니면 Unit에 출처 열을 더한다(빌더 판단).

### 9.6 문서 정보 제안
§6.3. 규칙 탐지는 추출 뒤 서버에서(업로드 응답에 반영). AI 보완은 새 AI 작업 종류.
