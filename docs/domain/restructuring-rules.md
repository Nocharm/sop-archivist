# SOP 재구성 판단 기준

- **출처**: TF·QA·AX팀 2026-07-08 회의 자료(39장). 괄호 안 숫자는 슬라이드 번호다. 그림 안의 글자와 연결선은 확인하지 않았다. 6절(고쳐 쓰기 원칙)은 이전 시도에서 정리한 원칙(킥오프 부록 D4)이다.
- **쓰임**: 앱의 AI 지침(분류·고쳐 쓰기·번역·짝 맞추기)의 원문이고, 테스트 정답 데이터를 만들 때의 근거다. AI는 이유를 낼 때 아래 ID를 인용한다.
- **ID**: `R01`–`R13`은 회의 자료 번호 그대로다. `S`·`X`·`Y`·`N`·`P`·`RW` 접두 ID는 인용을 위해 이 문서에서 붙였다. 내용은 회의 자료와 킥오프 그대로다.
- **고칠 때**: 이 문서는 앱 지침 버전의 시드다(제품 설계 §6.10). 내용을 바꾸면 앱에 새 지침 버전으로 올리고, 이전 버전으로 만든 AI 제안의 기록은 그대로 둔다.

## 2. SOP의 일곱 칸 (S) (18)

칸 키는 코드가 쓰는 고정 식별자다. 화면 표시 이름은 바뀔 수 있다(예: Electronic Record Control은 부서 간 논의에 따라 이름이 바뀔 수 있다).

| ID | 칸 키 | 칸 | 넣는 것 | 피할 것 |
|---|---|---|---|---|
| S1 | `purpose` | Purpose | 절차가 필요한 이유, 관리 목적 | SOP 내용 반복 |
| S2 | `scope` | Scope | 적용 대상(공정, 장비, 시스템, 부서) | — |
| S3 | `definitions` | Definitions | 문서 이해에 꼭 필요한 용어 | 일반적으로 통용되는 GMP 용어 |
| S4 | `responsibilities` | Responsibilities | 절차 안의 역할별 주요 책임 | 다른 절차에서 정한 일반 책임 |
| S5 | `general_requirements` | General Requirements | 이 SOP의 모든 절차에 공통인 요구사항 | 특정 절차에만 해당하는 내용 |
| S5.1 | `general_requirements.safety` | └ 안전(Safety) | | |
| S5.2 | `general_requirements.operation` | └ 작업(Operation) | | |
| S6 | `procedures` | Procedures | 업무·절차별 목적과 적용 시점, 업무 흐름, 주요 수행 단계 | 과도한 상세 작업 지시 |
| S6.1 | `procedures.procedure` | └ Procedure | | |
| S6.2 | `procedures.electronic_record_control` | └ Electronic Record Control (Audit Trail, Recipe 등) | | |
| S6.3 | `procedures.troubleshooting` | └ Troubleshooting | | |
| S6.4 | `procedures.maintenance` | └ Maintenance | | |
| S7 | `document_relationships` | Document Relationships | 관련 문서 맵핑 | 과도한 참조, 맞지 않는 내용 배치 |
| S7.1 | `document_relationships.attachments` | └ Attachments | | |
| S7.2 | `document_relationships.appendices` | └ Appendices | | |

- 장비 SOP의 Procedures 아래 S6.2·S6.3·S6.4는 내용이 없어도 N/A로 항목을 남기도록 권장한다.
- AI가 빈칸을 임의로 N/A로 채우면 안 된다. N/A에는 사유와 사람 확인을 남긴다.

## 4. 이행 (배경, 이 도구의 범위 밖)

- Legacy 문서의 실제 작업 지시는 새 문서로 옮기고, 옛 문서에는 안내 문구를 남긴다.
- SOP 하나에 Binder 하나를 구성한다. Binder에는 SOP와 WI 외에 Form, Training, Visual Aid, QRA가 들어갈 수 있다(24–25).

## 5. WI의 구조와 작성 (11, 19–23, 31–33)

**구조.** WI에는 SOP의 일곱 칸 같은 정해진 칸이 없다. 단계별 지시(Instruction)를 현장 작업 순서대로 쓰고, 필요한 단계에만 Why를 붙인다. How(작업 방법)와 Why(작업 이유)를 구분한다. 그래서 WI 안의 배정 위치는 "몇 번째 단계의 Instruction" 또는 "몇 번째 단계의 Why"다.

**Why를 붙이는 경우 (Y) (19)**

| ID | 경우 |
|---|---|
| Y1 | 작업자가 실수하기 쉬운 단계. 왜 중요한지 알아야 잘 지켜지는 경우 |
| Y2 | 눈으로 봐서는 중요성이 드러나지 않는 단계 |
| Y3 | 작업 순서를 반드시 지켜야 하는 단계 |
| Y4 | 주의사항의 근거를 설명해야 하는 경우 |
| Y5 | 교육할 때 질문이 반복해서 나오는 항목 |

**Why를 붙이지 않는 경우 (N) (19)**

| ID | 경우 |
|---|---|
| N1 | 모든 단계에 일괄적으로 설명을 붙이는 것 |
| N2 | GMP 상식 수준의 내용 |
| N3 | SOP에서 이미 충분히 설명한 정책 |
| N4 | 작업 수행에 도움이 되지 않는 이론 설명 |
| N5 | 행동의 결과를 되풀이하거나 규정을 반복하는 것 |

**좋은 예 (19, 31)**

- Instruction: 필터 하우징 상부 수동 밸브를 열어 약 5–10초간 클린 스팀을 블리딩한다. / Why: 하우징 내부의 잔류 공기와 응축수를 제거하고, 클린 스팀이 균일하게 접촉하게 하기 위함이다.
- Instruction: 파이펫팅을 최소화하여 샘플을 희석한다. / Why: 파이펫팅으로 생긴 기포 때문에 측정값이 부정확할 수 있다.
- Instruction: UFDF 장비의 압력 테스트와 SIP 전에 Membrane 홀더의 수동 밸브를 닫는다. / Why: 스팀으로 인한 Membrane 손상을 막기 위함이다.

**나쁜 예와 고치는 법 (19, 32)**

- Instruction: 이송 라인의 Clean Hold Time이 유효한지 확인한다. / Why: 클린 홀드 타임이 유효하지 않은 장비는 생산에 사용할 수 없다. → 규정을 반복할 뿐이다(N5).
- Instruction: 프로브 하우징이 올바르게 설치되었는지 확인한다. / Why: 올바르게 설치되지 않으면 전극이 제대로 된 값을 읽지 못할 수 있다. → 너무 기본적인 내용이라 Why를 지운다(N2).
- Instruction: 결과 평가를 위해 표준화 결과 평가 절차를 진행한다. / Why: 전극 상태를 판별하려면 표준화 후 결과 평가를 반드시 진행한다. → 지시문을 되풀이하므로 Why를 지운다(N5).
- Why 안에 Slope와 Offset의 정의, 전극 교체 지시가 길게 섞여 있다. → 작업자가 할 일은 Instruction으로, 꼭 알아야 할 용어는 Definition으로 옮긴다(X06).
- Instruction: 결과가 성공이라면 트랜스미터와 MCS 표시 값 확인 절차를 진행한다. → 이 확인은 프로브를 베슬에 설치하기 전 단계에서 지시해야 한다. 단계의 위치를 옮긴다(R04).

**QRA를 근거로 쓴 Why (33).** QRA의 위험 평가 결과(실패 모드, 영향)를 Why로 옮길 수 있다. 예: "샘플링 전에 충분히 교반됐는지 확인한다 / 균질하지 않은 상태에서 샘플링하면 결과가 편향될 수 있다". 다만 QRA에 없는 근거나 수치를 지어내지 않는다(X07).

**내용별 배치 (P) (20–23)**

| ID | 내용 | SOP에 둔다 | 독립 WI를 만든다 | 해당 WI의 단계에 둔다 |
|---|---|---|---|---|
| P1 | Troubleshooting | 단순한 정보 전달 | 여러 WI에 공통이고 단계별 해결 절차가 필요할 때 | 특정 작업 중에만 생기는 문제이고 그 WI 안에서 해결할 수 있을 때. 따로 섹션을 두기보다 문제를 예방하는 단계에서 지시한다. 예: "베슬 온도가 안정되지 않으면 P-test가 실패할 수 있다"(별도 섹션) 대신 P-test 앞 단계에 "베슬 온도가 안정되었는지 확인한다" |
| P2 | Maintenance | How-to 없이 주기만 알려 주면 될 때 | 상세한 단계별 절차가 필요하거나 여러 WI에 공통일 때. 예: Analyzer 카트리지·주사기·밸브 교체, 일상 청소 | — |
| P3 | Electronic Record Control (Audit Trail 검토 접속 방법, Recipe 관리) | 관리해야 한다는 요구사항만 있을 때 | 상세한 접속 방법이나 Recipe 관리 규칙이 필요할 때 | — |
| P4 | Appendix | 여러 WI에 공통인 내용. 예: 장비별로 WI가 여럿일 때의 장비 정보 | — | 특정 작업 중에만 확인할 정보. 장비별 WI가 하나뿐이면 장비 정보는 별도 섹션보다 WI 안에 둔다 |

- Maintenance처럼 절차가 짧아 판단하기 어려우면 두 경우로 나눠 본다. 다른 SOP에 상세 지시가 이미 있으면 그 SOP를 참조하도록 고친다. 단계별 절차가 필요한데 내용이 부족하면 내용을 보충해 독립 WI를 만든다(21).
- Appendix 내용 중 다른 문서에서 최신 정보를 확인할 수 있는 것은 지운다. FDS 요약본이나 장비 P&ID가 그 예다(23).
