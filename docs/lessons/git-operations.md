# git 운영 (히스토리 재작성·강제 푸시)

템플릿 분리(2026-11-08, 히스토리에서 템플릿 커밋 32개를 걷어 내고 `main`·태그를 강제 푸시) 때 실측한 시행착오다. 히스토리를 다시 쓰거나 원격 ref를 강제로 바꾸기 전에 먼저 읽을 것.

## ⚠️ 함정
1. **재작성 전에 같은 폴더의 다른 세션부터 확인한다 - lease는 예상 해시를 명시한다**: 임시 clone에서 재작성하는 사이 다른 Claude 세션이 같은 폴더에서 커밋·푸시해 원격 `main`이 움직였다. `--force-with-lease=refs/heads/main:<예상 해시>`로 값을 명시해 둔 덕분에 푸시가 `stale info`로 거부되어 그 커밋이 지워지지 않았다(값 없는 `--force-with-lease`는 원격 추적 ref를 기준으로 삼아, fetch가 끼면 같은 사고를 막지 못한다). 대처: 시작 전 `lsof -d cwd`로 그 폴더에서 도는 프로세스와 세션 목록, 최근 커밋의 `Claude-Session` 트레일러를 보고, 작업 중인 세션이 끝난 뒤 진행한다. 브랜치·태그는 `--atomic`으로 한 번에 보내 일부만 바뀌는 상태를 막고, 백업 번들(`git bundle create`)을 먼저 만든다. 재작성 결과는 커밋마다 트리·작성 정보를 대조한 뒤 푸시한다.
2. **zsh는 변수를 단어로 나누지 않는다 - 여러 인자는 배열로 넘긴다**: Bash 도구의 셸은 zsh라 `ARGS="--a=1 --b=2"; git push $ARGS …`가 공백째 인자 하나로 들어가 `cannot parse expected object name`으로 실패했다(이때는 아무것도 푸시되지 않았다). `args=(--a=1 --b=2); git push "${args[@]}" …`처럼 배열을 쓴다. 같은 이유로 `while read … done < <(…)` 안에서 문자열을 이어 붙여 인자 목록을 만들지 않는다.
