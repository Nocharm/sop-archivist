## 2. 정한 것

1. **부여 = 목록 + 상세(1:2)** — 왼쪽 대상 목록(한 줄 = 대상 하나, 숫자 = 받은 역할 수), 오른쪽 상세(직접 받은 것 / 부서로 받은 것 / 유효 권한 / 최근 변경). "유효 권한 조회" 하위 메뉴는 흡수한다 — 찾기에서 부여가 없는 직원도 찾는다("부여 없음 · 직원 목록에서 찾음" 묶음).
2. **자연어 일괄 등록 = 사내 AI가 읽고, 대상은 로그인 ID로** (사용자 결정 2026-11-21)
   - ~~보내기 전 브라우저 검사: 직원 이름과 정확히 같은 말은 ID로 바꿔 보낸다. 동명이인이면 고를 때까지 읽기 단추가 잠긴다. 목록에 없는 이름처럼 보이는 말은 `[이름 지움]`으로 바꿔 보내지 않는다.~~ (2026-11-26 실명 규칙 완화로 하지 않음 — 머리말)
   - AI 결과: 줄마다 새로 / 이미 있음 / 회수 / 목록에 없음. 없는 ID는 화면에서 확인만, 반영하지 않는다. 확정 전에는 아무것도 바뀌지 않는다. ~~"보낸 글 보기"로 AI에 간 글을 보여 준다.~~ (완화 뒤에는 보낸 글이 적은 글 그대로라 두지 않음)
   - AI가 꺼지거나 실패하면 창에 안내를 띄우고 사람 경로(한 명씩 더하기)는 그대로 돈다.
   - ~~**규칙 문서 고침이 필요하다**: `backend/CLAUDE.md` "AI 호출: 페이로드에 직원 실명 금지"와 제품 명세 §646(앱이 덧붙이는 정보에 실명·로그인 ID 넣지 않음)에 "자연어 등록은 사용자가 쓴 로그인 ID·부서 코드·역할 이름까지 허용, 실명 금지(브라우저가 이름을 ID로 바꾸고 못 바꾼 이름은 지움)"를 사용자 결정으로 적는다. 서버도 보내기 전에 같은 검사를 한 번 더 한다(브라우저 우회 대비).~~ (2026-11-26 실명 규칙 완화로 하지 않음 — 머리말)
   - MCP는 하지 않는다(외부 모델로 명단이 나가고, 도구가 바로 쓰면 "AI 제안·사람 확정"과 어긋남, 별도 토큰·서비스 필요).
3. **일괄 저장 API** — `POST /api/access/grants/batch`: 추가·회수를 한 트랜잭션에, 이미 있는 것은 건너뛰고 결과(added/removed/skipped/unknown)를 돌려준다. 항목마다 감사 기록. `permission.manage`. Alembic 없음.
4. **bpm 참고 범위** — 배치·고르기 링·필 필터·상태색 타임라인·호버 명단 미리보기만. 바이올렛·유리 효과는 쓰지 않는다(디자인 기초 3절).
5. **한 명에게 역할 더하기 = 그 줄에 붙어 뜨는 고르기**(화면을 어둡게 하지 않음, 키 `A`). **부여 한 건 회수 = 확인 모달 대신 5초 되돌리기 토스트.** 여러 건 회수·삭제는 확인 모달.
6. **긴 목록 = 이어 불러오기** — 30개씩, 끝에서 실제 줄 높이의 빈 줄을 잠깐 보인 뒤 붙인다. "60 / 324 보임". 부여 목록·Bundle은 기존 `useProgressiveList`, 변경 기록은 서버 커서(`before`)가 필요하다.
7. **2단 화면 전환** — 마우스로 고르면 상세 틀·머리는 그대로, 이전 내용을 45%로 흐리게 두고 새 자료가 오면 140ms 페이드(`Refresh`). 키보드 `↑↓`는 페이드 없이 즉시(디자인 기초 4절). 탭 전환은 본문만 페이드. 거르기는 남은 줄이 미끄러짐(`useFlip`). 움직임 줄이기면 모두 즉시.
8. **레일 묶음 제목** — 사람·권한(부여·역할·변경 기록) / 운영(직원 동기화·배치 작업·AI) / SOP 기준(Bundle·AI 지침·표준 골격).

## 3. 화면 규칙 (모든 관리 표·목록)

- **줄 높이 52px**(두 줄 칸 56), 칸 좌우 16px, 머리 줄은 배경 없이 흐린 작은 글자, 짝수 줄 아주 옅은 바탕, 올린 줄은 선택색.
- **한 칸 두 줄은 종류가 다른 정보일 때만** — 윗줄 이름(굵게), 아랫줄 작고 흐린 글(ID·부서, 설명, 코드, 키, 일정). 같은 종류를 둘로 꺾지 않는다. 숫자·날짜·상태·만든 사람은 한 줄.
- **이름이 보이면 머리글자 동그라미를 쓰지 않는다** — 겹친 명단(역할의 받은 대상, Bundle 구성원 요약)처럼 이름이 다 안 들어갈 때만. 부서는 이름 앞 글자 크기의 흐린 아이콘만.
- 칩은 테두리 없이 옅은 채움(역할 파랑, 그 밖 회색, 직접 준 권한만 점선). 상태는 색 점 + 글, 진행은 숫자 옆 막대.
- 편집 칸(표준 골격)은 평소 글처럼, 올리거나 초점이 가면 테두리 — 보기·고치기 크기가 같아 움직임 0.
- 단추 자리: 만들기 = 패널 머리 오른쪽 / 줄 동작 = 줄 끝(올렸을 때만) / 여러 개 고른 뒤·바뀐 칸 저장 = 아래 가운데 떠 있는 띠 / 모달 주 단추 = 바닥 오른쪽 끝, 위험한 동작은 떨어진 왼쪽.
- 틀이 움직이지 않게: 단추 폭 고정(`BusyLabel`·`MorphWidth`), 목록 `scrollbar-gutter: stable`, 스켈레톤은 실제 줄 높이로 200ms 뒤에만.

## 5. 지킬 것

- 버전·CHANGELOG는 이 모음 브랜치에서 올리지 않는다(2026-11-25) — `dev`에 합칠 때 쪼개기 먼저 쪽과 맞춰 정한다.
- 화면·라벨을 바꾸는 커밋에서 `frontend/public/manual/user-manual.md`의 관리 절 글도 고친다(그림은 정식 업데이트 때 바뀐 장면만).
- 새 권한은 없다. 새 i18n 키는 en·ko 둘 다. 서버 거절 코드를 새로 만들면 `rule.<code>` 문구.
- 운영 DB에 실자료가 있다 — 이번 일은 Alembic 없음. 생기면 사용자 승인.
- 검증: 관리 화면 스모크는 `frontend/scripts/pw-smoke-baseline.mjs`(관리 탭·권한 식별자 `admin-tab-*`·`access-sub-*`·`grant-*`를 쓴다 — 식별자를 바꾸면 이 스크립트도 같은 커밋에서). 스텝마다 새 화면 단계를 더하고 기대값을 낮추지 않는다. 공용 부품은 건드리지 않으므로 전체 스모크·감사 넷 대신 관리 스모크와 관리 장면 감사만 한다. 하위 에이전트는 서버·브라우저를 띄우지 않고 model을 명시한다.
